How access is decided

The same logic runs in four places: the app, firestore.rules, storage.rules and Cloud Functions. The rules protect the data. The app only hides the menus.

Step 1
Active team
users/{uid}.teamId selects the team. A person can be on more than one team and switch in the header.
Step 2
Member record
teams/{team}/members/{uid} holds the role, accessLevel and workspaceOverrides.
Step 3
Level gives a base set
For example, planner gives 11 workspaces. A missing level counts as internal for owners and admins, and as planner for members.
Step 4
Overrides change single workspaces
true adds a workspace. false removes it. Overrides always win over the level.
Step 5
Result
The workspaces the person can open, plus the team data that the rules let them read.
Team package and exceptions

The team package (defaultMemberAccessLevel + overrides) is what a new member gets when they join with the invite. When you change the package, members who matched the old package move to the new one. Members with different access are exceptions: they keep their own access and show a Custom badge.

Data from another team

dataSourceTeamIds lets a partner team read another team's Transit App, STREETS, Fleet Plan, Master Schedule or Strategic Plan data. For example, WATT can read Barrie's Transit App data. Only you can set this, and only in an edit session.

Packages

The choices in the Access tab. Each package is an access level plus optional overrides.

How people join

Path A
They create their own team
They become owner with none. They see only Team Management until you grant access. Shaw's team was created before this protection.
Path B
You create a partner team
Team Management → New team. Choose a package and send the invite link (?invite=CODE). Members join as member with the package.
Path C
They enter an invite code
Same result as Path B. The rules refuse any access other than the team package or none.

Your support tools

Inspect as (read-only)

Members tab → Inspect as shows the app exactly as that member sees it, or Support → Inspect team default. Use this to check what a team really sees.

Caution: if you choose a team from the header team menu, the inspect session uses internal, so every workspace shows. That view does not show the team's real access.

Edit session (up to 60 minutes)

Support → Start edit. You must give a reason, which goes into the audit log. You get owner-level writes on that team. You need it to change a team you are not a member of, or to set data sources.

Your own team: you always get internal, whatever your member record says.
